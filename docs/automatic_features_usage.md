# Запуск исследования автоматических признаков

Реализованы коммиты 15–24: малый реальный эксперимент, основной поиск и
внешняя валидация выполнены, метод зафиксирован. Основная тестовая оценка
нового метода ещё не выполнялась и относится к коммиту 25.
Протокол: [automatic_features_protocol.md](automatic_features_protocol.md).

## Окружение и входные артефакты

Используется то же окружение и `requirements.lock`, дополнительных зависимостей нет.
Нужны подготовленные данные, сохранённые кэши, модели и манифесты первого этапа,
включая дополнительную абляцию групп признаков. Пакет проверяет их SHA и версии.
Модели и данные исключены из Git: на новой машине сначала воспроизведите первый
этап по README и выполните `python -m scripts.feature_ablation` с его конфигурацией.
После этого укажите соответствующий `baseline_config` в исследовательском TOML.

Исследование использует frozen baseline как вход; команда `reproduce` повторяет
вторую часть с нуля, а не загружает данные и не переобучает первый этап.
Завершённые исходные результаты не перезаписываются.

## Поэтапное выполнение

Из корня проекта, Python из `.venv`:

```bash
.venv/bin/python -m kion_autofeatures prepare
.venv/bin/python -m kion_autofeatures search
.venv/bin/python -m kion_autofeatures validate
.venv/bin/python -m kion_autofeatures freeze
.venv/bin/python -m kion_autofeatures test
.venv/bin/python -m kion_autofeatures verify
```

`prepare` только проверяет и фиксирует входы. `search` использует внутренние
срезы 19/26 июля → 2 августа. `validate` оценивает семь заранее заданных вариантов
на 9 августа. `freeze` фиксирует метод и контрольные суммы. `test` сначала
заканчивает все четыре переобучения, затем строит финальные цели и оценивает
модели. Повторный `test` проверяет сохранённые результаты и не обучает модели.
`verify` загружает сохранённые модели, воспроизводит прогнозы и качество.

Для нового полного воспроизведения второй части:

```bash
.venv/bin/python -m kion_autofeatures reproduce --name reproduction_01
```

Имя должно быть новым. Можно закончить раньше: `--through validate`.
После прерывания продолжайте нужной поэтапной командой с тем же `--name`;
завершённые совместимые этапы используются повторно. Несовместимая конфигурация,
код или повреждённый артефакт приводят к ошибке, а не к тихому переобучению.
После freeze новый поиск закрыт; для изменения метода нужен новый эксперимент.

## Артефакты и ресурсы

Настройки — `autofeatures.toml`. По умолчанию результаты в
`results/autofeatures/main`, модели и кэши в `artifacts/autofeatures/main`.
`inputs.json` — происхождение; `selection.json` — выбранные/случайные признаки,
описания и журнал удаления; `validation_results.csv` и `test_results.csv` — качество;
`*_intervals.json` — парные интервалы; `test_segments.csv` — сегменты;
`frozen.json` — зафиксированный метод. Временные метки этапов записываются в UTC.

Каждый тяжёлый этап запускается в отдельном дочернем процессе. До импорта
числовых библиотек выставляются лимиты потоков. Одновременно разрешён один
исследовательский процесс; лимит — два вычислительных потока и 6 GiB суммарного
RSS дочернего процесса и его потомков. Общие страницы могут учитываться повторно.
При превышении процесс завершается; уже завершённые этапы сохраняются.
Если среда запрещает наблюдать память дочернего процесса, запуск завершается
с диагностикой; ограничение RSS не отключается автоматически.
Прерванная модель не считается завершённой и обучится заново при продолжении.
Логи и отдельные замеры процессов — в `artifacts/autofeatures/ИМЯ/resources`.

В model receipts раздельно записаны время Pool, fit, predict (медиана трёх
повторов после прогрева), размер модели и RSS процесса в измеренном интервале.
RSS включает загруженные данные и не означает размер только модели.
Генерация записывает время вычисления кэша, время текущего обращения, RSS и байты;
при повторном обращении исходное время построения не выдаётся за новый расчёт.
Рабочий этап поиска имеет собственный полный замер времени/RSS в `resources`.
Общий retrieval сохранён; его метаданные и история нужны даже моделям без S.
Кэшированное чтение готовых кандидатов не является замером построения retrieval.
Историческое время обучения baseline приводится отдельно от текущих измерений.

## Проверки реализации

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m kion_autofeatures --help
```

Тесты используют маленькие синтетические данные и не запускают основной поиск.
Малый реальный эксперимент и аудит длительности выполнены в коммите 23,
основной поиск и внешняя валидация — в коммите 24. Итоговый тест относится
к коммиту 25, итоговый отчёт и ноутбук — к коммиту 26.

Малый реальный эксперимент выполнен: [результат и аудит](automatic_features_pilot.md).
Он воспроизводится командой `python -m scripts.autofeatures_pilot` в отдельном
каталоге и использует более ранний исторический условный тест.

Текущий [валидационный отчёт](../results/autofeatures/main/VALIDATION.md)
воспроизводится без обучения:

```bash
.venv/bin/python -m scripts.build_autofeature_validation_report
```

Для другого имени исследования укажите `--name NAME`. Генератор отчёта также
проверяет совпадение упорядоченных пар, пользователей, целей и candidate recall
во всех семи вариантах. Он читает готовые артефакты и не меняет зафиксированный
метод. Проверка сохранности исходных 65 файлов baseline, загрузки моделей и
результат 37 тестов записаны в
[validation_verification.json](../results/autofeatures/main/validation_verification.json).
