# Ручные признаки baseline

Для каждого среза используются только строки с `last_watch_dt < cutoff`.
Окна: последние 7, 30, 90 дней и вся доступная история (`all`).
Признаки относятся к записям о последних просмотрах пар KION, а не к восстановленному журналу повторных просмотров.

## Пользователь и фильм

| Семейство | Определение |
|---|---|
| `u_count_*`, `i_count_*` | Число исторических записей в окне |
| `u_recency`, `i_recency` | Дней от последнего наблюдения до среза |
| `u_observed_age`, `i_observed_age` | Дней от первого наблюдения до среза |
| `*_total_dur_mean` | Среднее `log1p(total_dur)` по историческим строкам; длительность в секундах |
| `*_watched_pct_mean` | Средний исторический процент просмотра без пропусков |
| `*_total_dur_missing`, `*_watched_pct_missing` | Нет ни одного валидного значения для соответствующего среднего |
| `*_trend_7_30` | `(count_7 + 1) / (count_30 + 1)` |
| `u_active_days` | Число различных дней взаимодействий |
| `u_genre_diversity` | Число встречавшихся жанров |

Категории пользователя: возрастная группа, доход, пол, признак детей. Они могут отсутствовать.
Категории фильма: ID, тип контента, первая указанная страна, первый режиссёр и нормализованная комбинация жанров.
Числовые метаданные: год выпуска, признак детского контента и возрастной рейтинг, каждый с индикатором пропуска.

## Связь пользователя и кандидата

- `pair_genre_count_*`: скалярное произведение исторического профиля жанров пользователя и жанров кандидата.
  Исторический фильм распределяет единицу поровну между своими жанрами; кандидат также имеет веса `1 / число жанров`.
- `pair_genre_share_*`: соответствующий счётчик, делённый на число взаимодействий пользователя в окне (минимум 1).
- `pair_genre_recency`: давность самого недавнего взаимодействия хотя бы с одним жанром кандидата.
- `pair_directors_count_*`, `pair_directors_share_*`: число и доля взаимодействий с первым режиссёром кандидата.
- `pair_content_type_count_*`, `pair_content_type_share_*`: число и доля взаимодействий с типом контента кандидата.
- `pair_*_recency`, `pair_*_missing`: давность соответствующей связи и индикатор её отсутствия.

Отсутствующая связь имеет счётчик 0 и давность 999 с индикатором пропуска.
Прямые счётчики повторных просмотров пары не используются: уже наблюдавшиеся пары исключены из кандидатов.

## Источники кандидатов

Для `pop`, `recent`, `knn`, `genre` хранятся `cand_*_score`, `cand_*_rank`, `cand_*_present`.
Отсутствующий источник имеет позицию `source_limit + 1`; его числовой балл, если определён для фильма, сохраняется.

- `pop`: число взаимодействий фильма за всю историю.
- `recent`: число взаимодействий за 7 дней.
- `knn`: сумма сходств с последними 100 фильмами пользователя. Сходство — cosine бинарных
  взаимодействий, умноженный на `co_count / (co_count + 10)`; у каждого фильма до 100 соседей.
- `genre`: историческая доля жанров пользователя, скалярно умноженная на жанры кандидата и
  умноженная на `log1p(популярность фильма за 7 дней)`.
- `rrf_score`: сумма `1 / (60 + rank)` по источникам, предложившим фильм.

Все контрольные методы оцениваются на том же объединённом пуле до 200 кандидатов.
Это протокол сравнения ранжирования на общем пуле; каталог целиком не скорится каждым методом.

## Служебные поля

`user_id`, `item_id`, `query_id`, `cutoff`, `label` не передаются в модель.
Идентичность фильма передаётся отдельно как категориальный `i_id`.
Функция построения признаков не принимает будущие labels.

## Диагностическая абляция

Из 82 признаков удаляются `pair_*`, `cand_knn_*`, `cand_genre_*` и `rrf_score`; остаются 45.
Сохраняются все характеристики пользователя и фильма, признаки популярности и общий
персональный пул кандидатов. Бустинг по-прежнему может строить взаимодействия между
признаками пользователя и фильма. Поэтому сравнение проверяет вклад явных связей и
персональных баллов источников, а не полное отключение персонализации.
